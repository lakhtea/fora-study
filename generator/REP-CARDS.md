# Rep cards for reps 07 to 25

Reps 01 to 15 are built (cards 07 to 15 are kept below for reference; rep 10 used R4 instead of R5, because `onClick={fn()}` is a compile error in TypeScript unless the handler returns `any`). Each remaining card is the design for one more rep, at the same standard: three compound bugs, observable within three steps, PM-voiced tickets, a key with the full format, verified by `npm run verify NN` and `npm run solution NN`. Generate them with `GENERATE-REP.md` in Claude Code, one at a time, in order. Classes are from the taxonomy in `GENERATE-REP.md`.

Covered so far: E1 T3 D3 | L1 T1 E6 | R1 T6 D1 | E2 T2 D5 | E4 T4 D2 | R3 T5 E8 | E5 T7 D4 | F1 T3 D6 | M1 T1 D6 | R4 T6 E6 | R2 T2 D1 | E3 T4 D5 | R7 T5 D2 | L3 T7 E8 | F2 T3 D4. The cards finish the taxonomy by rep 19 and then repeat the highest-value classes in new settings.

**07 trips-timeline** (page: a client's trips on a timeline with a search box and a detail drawer). A: E5 delay instead of debounce, with a visible "requests sent" counter so the per-keystroke firing is felt. B: T7 prop contract mismatch: the drawer's `onClose` is passed as `onDismiss`, child typed with an optional prop, so Close does nothing. C: D4 date-only strings parsed as UTC midnight, trips show one day early for a New York user; the London colleague sees it right.

**08 payout-dashboard** (page: payout threshold settings, a chart of monthly payouts as a table, a "next payout" estimate). A: F1 controlled input initialized to undefined (threshold field drops the first keystroke and warns). B: T3 again in a new setting: payout ids from a `<select>` are strings, the "mark as reviewed" lookup misses. C: D6 stale derived value: the next-payout estimate is memoized on `rows` but reads `threshold` from a closure.

**09 supplier-onboarding** (page: a supplier form with a document checklist, a "completion" ring, and a submit). A: M1 memo defeated by an inline object (`style={{...}}`) on a heavy checklist row with a render counter. B: T1 non-null assertion on `documents.find(d => d.kind === required)!` crashing when a required kind is missing. C: D6 again: completion percent memoized with a missing dependency on the required-kinds list.

**10 share-view** (page: the client-facing read-only itinerary with a day picker and a map placeholder). A: R5 `onClick={select(day)}` invoked at render, so the picker jumps and re-renders in a loop until it settles on the last day. B: T6 optional chaining on a share token lookup turns "expired" into an empty page with no message. C: E6 out-of-order: switching days quickly shows the wrong day's items (latency scales with item count).

**11 deals-board** (page: supplier deals with filters, a "selected deals" tray, and a count badge). A: R2 reading state right after setState when building the tray payload, so the badge lags one behind. B: T2 any letting `deal.validUntil` arrive as an object `{ date, tz }` and render as `[object Object]`. C: D1 `sort` mutating the deals array feeding two views.

**12 notifications-center** (page: a feed with mark-as-read, filters, and an unread counter in the header). A: E3 effect that sets the state it depends on, causing runaway refetches once a filter is active (visible request counter). B: T4 literal mismatch: filter values "Unread"/"Read" against "unread"/"read". C: D5 money math: a "savings this month" total concatenates decimal strings in a reduce.

**13 traveler-profiles** (page: a client's travelers with a per-traveler notes editor and a passport-expiry warning). A: R7 a hook called conditionally (an effect inside `if (traveler.hasPassport)`) breaking hook order when you switch from a traveler with a passport to one without. B: T5 index signature: `expiryByTravelerId[id].slice(...)` for a traveler with no passport. C: D2 off-by-one: "expires within 6 months" uses an exclusive month boundary so the last day is excluded.

**14 room-blocks** (page: group room blocks with rooms assigned to travelers, drag replaced by Up/Down, and a "unassigned" list). A: L3 child keeps stale local state when the selected block changes (missing key reset on the assignment form). B: T7 again: `onAssign(roomId, travelerId)` called with the arguments swapped where the child typed both as `number`. C: E8 a failed assignment request leaves "Assigning" forever; the server rejects double assignment.

**15 price-alerts** (page: Price Drop subscriptions with a check history and a toggle per subscription). A: F2 the "add subscription" form submits without preventDefault, reloading the page (state lost; CoderPad preview reloads). B: T3 a booking reference typed as number but it's a string like "FORA-610233", so the equality check on subscribe never matches. C: D4 again: the next-check time is computed from a date-only string.

**16 commission-rules** (page: a rules editor where each rule is a row with conditions and a rate, a preview of the computed commission for a sample booking). A: M3 state too high: typing the rate re-renders a 2,000-row preview table (render counter plus synthetic cost). B: T6 nullish default: a missing rate for a supplier tier becomes 0% silently. C: D6 the preview is memoized on `rules` but `rules` is mutated in place by the row editor (pairs the memo with R1-style mutation; the fix is immutable updates).

**17 client-import** (page: CSV paste, a parsed preview table, duplicate detection against existing clients, and Import). A: L2 duplicate keys when two pasted rows share an email, causing flaky updates when you edit the preview. B: T2 wrong shape: the existing-clients response wraps rows in `{ data: { clients } }`, so the duplicate check sees undefined and flags nothing. C: D3 merge collision: pasted rows merged with defaults in the wrong order, so every imported client gets status "prospect" even when the CSV says "active".

**18 messages-thread** (page: a client message thread with a composer, optimistic send, and a "typing" indicator from a mock channel). A: E7 an async function passed directly to `useEffect` for the channel subscription, so cleanup never runs and messages duplicate after switching threads. B: T4 `status: "Sent" | "Delivered"` compared against lowercase from the server, so every message shows a clock icon. C: E6 out-of-order: the thread for a previous client overwrites the current one when switching fast.

**19 availability-calendar** (page: a month grid of availability for one supplier with a nights selector and a "book these nights" summary). A: F4 wrong event property: the nights `<select>` handler reads `e.target.checked`. B: T1 `grid.find(cell => cell.date === selected)!` after the month changes. C: D4 a third variant: nights counted across a DST change using local midnight math give 29 nights instead of 30.

**20 team-leaderboard** (page: advisor leaderboard with a period picker, rank movement arrows, and a "my rank" card). A: M2 context value recreated every render (the period and the rows in one object), so the whole board re-renders on a clock tick (render counters). B: T5 `rankByAdvisorId[myId].position` for an advisor not yet ranked. C: D1 `reverse()` mutating the shared rows when the sort toggle flips.

**21 refund-requests** (page: a refund queue with approve/deny, a reason textarea per request, and filters). A: L1 index keys with an uncontrolled reason textarea, so denying the first request moves its reason to the next. B: T6 a nullish default turns a 403 ("not your request") into a silent no-op; the row stays. C: E8 approve hangs on "Approving" when the server returns 409 (already decided).

**22 trip-costs** (page: a trip's cost breakdown by category with an FX rate input and a client-currency total). A: E2 effect deps: the FX conversion effect depends on `trip` but not `rate`, so changing the rate doesn't update the total until something else does. B: T3 the FX rate from the input is a string and `amount * rate` works but `amount + fee` concatenates (two boundaries in one page; the fix is one parse). C: D5 cents versus dollars: one category arrives in cents and is summed with dollars.

**23 supplier-contacts** (page: a supplier's contacts with inline edit, a primary-contact radio, and a save bar). A: R5 handler invoked at render, made compile-safe by an analytics helper typed to return `any` (`onClick={trackClick("save")}`), so the event fires on every render and the click does nothing. B: T7 the radio's `onChange` prop is named `onSelected` on the child and typed loosely, so picking a primary contact does nothing. C: D3 merge collision: contact edits merged over the original with the original spread last, so edits disappear on save.

**24 hackathon-votes** (page: a hackathon project list with one vote per advisor, live counts via polling, and a "my vote" marker). A: E4 a polling interval set in an effect without cleanup, so counts update faster and faster as you switch tabs (visible interval counter). B: T4 `voteState: "voted" | "open"` compared against "Voted". C: E6 a poll response for a previous project list overwrites the current one.
